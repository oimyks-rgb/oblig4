The TO-BE process still covers them with US-15 (driver delivery list, marked ASSUMPTION in the backlog) and US-25 (payment status sync).

## Notation notes

- **Pools:** *Customer* is its own pool, so the hand-offs with Ekte Mat are shown as message flows (dashed lines). In BPMN, message flows can only connect separate pools; lanes in the same pool are linked by sequence flows. *Ekte Mat AS* holds the lanes Event coordinator, Kitchen, Driver and Owner (AS-IS), with Ekte Mat Online added as a lane in the TO-BE diagram. *Fiken / Vipps* is shown as a collapsed (black-box) pool in the TO-BE diagram.
- **Gateways:** exclusive gateways split and merge the alternative paths. The event-based gateway waits for either the customer's acceptance or a timeout, so the process never stalls.
- **Linting:** both files pass `bpmnlint` with its recommended rules and were rendered with bpmn-js. The .bpmn files open in Camunda Modeler, bpmn.io or Signavio.
