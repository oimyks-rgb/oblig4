# Plan: A2 Images for food items (Gemini illustrations + uploads)

## Context

Assignment A2: "Upload a picture for each item, or write an instruction that an AI agent or image service uses to create or modify the picture. The admin previews the result before it is saved."

What you asked for:
- **Default images:** Gemini generates a simple illustration for each food item.
- **Uploads:** staff can upload their own picture in the admin panel instead.

A1 (merged in #2) gives food items an `image_filename` that nothing sets yet. The menu shows a placeholder.

Gemini facts (checked 2026-10-27 on ai.google.dev):
- **Models:** the image models are `gemini-nano-banana-2.1` and `gemini-3.1-flash-lite-image`, which is the cheapest and supports 1K only.
- **SDK:** `google-genai` (2.33) calls `client.interactions.create(model=…, input=… [, image part])` and returns base64 in `interaction.output_image.data`.
- **Cost:** there is **no free tier** for image models. They cost about **$0.034 per 1K image**, so 11 seed items cost about $0.40. That means a Gemini API key with billing.
- **Watermark:** every generated image carries a SynthID watermark.

Storage (decided earlier): local disk, behind an `ImageStore` interface. To share the generated defaults without everyone paying to regenerate them:
- generated **seed illustrations are committed to git** in `seed_images/`
- image names are **content hashes**, so the same picture gets the same name on every machine
- `seed.py` loads the committed illustrations into each member's local store

Pictures staff upload or generate in the admin panel stay on the computer they were made on. Other members see the placeholder.

Branch `feature/a2-images`. Commit this plan as `docs/plans/2026-10-27-a2-images.md`, then open a PR.

## Model layer (`app/models/`)

- **`images.py`** (new)
  - `process_image(data) -> bytes`, using Pillow:
    - accepts JPEG, PNG or WebP up to 5 MB, otherwise `ImageError` with a user-facing message
    - applies `exif_transpose`, converts to RGB and shrinks to fit 1200×1200
    - saves as JPEG at quality 85, which strips EXIF/GPS data
  - `image_name(data)` is `sha256(data)[:32] + ".jpg"`.
  - `ImageStore` (an ABC) with `save(data, draft=False) -> name`, `read`, `exists`, `delete`, `promote(draft) -> name` and `cleanup_drafts(max_age)`.
    - Drafts are named `draft-<uuid>.jpg`.
    - Every name is checked against `^(draft-)?[0-9a-f]{32}\.jpg$`, which blocks path traversal.
  - `LocalImageStore(folder)` uses `instance/images/`, which is git-ignored via `instance/`.
- **`memory.py`**: a `MemoryImageStore` for tests.
- **`image_generation.py`** (new)
  - `ImageGenerator` (an ABC) with `create(instruction) -> bytes` and `modify(image, instruction) -> bytes`. Failures raise `ImageGenerationError` with a readable message.
  - `GeminiImageGenerator(api_key, model)` calls `interactions.create` with `response_format={"type": "image", "aspect_ratio": "4:3", "image_size": "1K"}`. For modify, it adds the current picture as an image part. It decodes `output_image.data`.
  - `FakeImageGenerator` draws a card with the text using Pillow. It's used in tests and for trying the flow without a key.
  - `default_illustration_prompt(item)` gives one consistent style for every item: "A simple flat vector illustration of {name} ({description}), a Norwegian catering dish, centred on a plain warm off-white background, soft colours, no text, no people, no logos." Staff can edit it before generating.
- **Wiring:** `repositories.py` gets `images: ImageStore` in `Repositories`. `create_app` builds the image store and the generator from `.env`:
  - `IMAGE_GENERATOR` is `gemini`, `fake` or empty (off)
  - `GEMINI_API_KEY` holds the key
  - `GEMINI_IMAGE_MODEL` defaults to `gemini-3.1-flash-lite-image`
  - an `image_generator()` helper sits next to `repos()`

## Controllers

- **`shop.py`**: `GET /images/<name>` serves the picture from the store with a long cache header, or 404 for unknown or invalid names.
- **`admin.py`** (`@admin_required`, under `/admin/food-items/<id>/image`):
  - `GET …/image`: shows the current picture or the placeholder, plus three ways to get a new one:
    1. Upload a file.
    2. Generate an illustration. The textarea is prefilled with `default_illustration_prompt(item)`.
    3. Modify the current picture with an instruction (only when a picture exists).
    
    Options 2 and 3 are hidden when no generator is configured. The page also has a "Remove picture" button.
  - `POST …/image/upload` and `POST …/image/generate` (with `mode=create|modify` and an instruction of at most 1000 characters): both call `process_image`, save a draft and store the draft name in the session, then redirect to the preview. Errors are shown on the page with status 400 (bad file) or 502 (Gemini error).
  - `GET …/image/preview`: shows the current and new picture side by side, with Save, Discard and Try again.
  - `POST …/image/save`: promotes the draft, updates `image_filename` and deletes the old picture if no other item uses it.
  - `POST …/image/discard` and `POST …/image/remove` do what their names say.
  - Each new draft first calls `cleanup_drafts(1 day)`.
- **`create_food_item`** now redirects to the new item's picture page, so staff can add a picture right away.
- **Config**: `MAX_CONTENT_LENGTH = 8 MB`, with a 413 handler that flashes "File too large".

## Batch generation for the seed items

- **`generate_images.py`** (new, CLI): for each item in `seed.FOOD_ITEMS`, it generates the default illustration with the configured generator, processes it and writes `seed_images/<item-id>.jpg`.
  - It skips items that already have a file, unless `--force` is given.
  - It prints the estimated cost and asks for confirmation before calling Gemini.
  - One group member runs it once and commits `seed_images/`.
- **`seed.py`**: when `seed_images/<id>.jpg` exists and the item has no picture, or has a seed picture with a different hash, it saves the file to the local store and sets `image_filename`. Content-hash names make this identical on every machine.

## Views

- `admin/food_items/image.html` and `image_preview.html`. The upload form uses `enctype="multipart/form-data"`, `accept="image/jpeg,image/png,image/webp"` and a CSRF token. A "Generating… this takes about 10 s" message shows while waiting.
- `list.html`: a thumbnail column and a "Picture" action. `form.html`: a thumbnail with a link.
- `shop/index.html`: the card uses `url_for('shop.image', name=…)`, with `onerror` falling back to the placeholder.

## Tests (no network)

- **`tests/test_images.py`:**
  - `process_image` resizes, converts PNG to JPEG, rejects text and oversized files, and strips EXIF.
  - A shared store contract test runs against both `LocalImageStore` (`tmp_path`) and `MemoryImageStore`: content-hash names, drafts, promote, cleanup and name validation.
- **`tests/test_image_generation.py`:**
  - `GeminiImageGenerator` is tested with a fake client injected through the constructor. It checks the model, prompt, image part and `response_format` sent, base64 decoding, and that an SDK error becomes `ImageGenerationError`.
  - It also tests `default_illustration_prompt`.
- **`tests/test_admin_images.py`**, using `FakeImageGenerator`:
  - upload, preview, Save; Discard; Remove; generate (create and modify), preview, Save
  - a bad file returns 400
  - the generator options are hidden when it's off
  - a customer gets 403
  - `/images/` returns 404 for unknown names and `../`
- **`tests/test_seed_images.py`:** the seed loader stores files and sets names using the memory backend.
- **`requirements.txt`:** add `Pillow>=12` and `google-genai>=2.30`.
