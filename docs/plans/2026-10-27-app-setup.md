## Key design points

- **Graph model.** `(:FoodItem {id, name, description, priceNok, minOrderQty, dietaryLabels, published, imageFilename})`, `(:FoodItem)-[:CONTAINS]->(:Allergen {code})`, `(:FoodItem)-[:SUITS]->(:EventCategory {code})`, `(:User {id, email, name, passwordHash, role})` where role is `customer` or `admin`. Allergens and event categories are nodes, so later queries like "today's orders with nuts" or "menu for weddings" are graph traversals. The repository hides this: `FoodItem.allergens` is just a list of codes.
- **Constraints.** `ensure_schema()` runs `CREATE CONSTRAINT … IF NOT EXISTS` for unique `FoodItem.id`, `User.email`, `Allergen.code` and `EventCategory.code`. It is called by `seed.py`.
- **Swappable backend.** `create_app` picks `Neo4j*Repository` or `Memory*Repository` from `REPOSITORY_BACKEND`. Controllers only call `repos().food_items.list(...)`.
- **Passwords.** Hashed with `werkzeug.security`, which ships with Flask. Login routes are not part of this step. They come with the C3/admin-auth plan.
- **Seed (`seed.py`).** Loads `.env`, calls `ensure_schema()`, and uses `MERGE` on a fixed id/email to add about 10 synthetic food items across all event categories, one admin `admin@ektemat.test` and two customers `@ektemat.test`. Passwords come from `SEED_*_PASSWORD`. `--reset` asks for confirmation, then runs `DETACH DELETE` on everything. Rerunning without it is safe.
- **Neo4j tests on the shared database.** Test data uses ids prefixed `test-` and emails ending `@test.invalid`. A fixture deletes exactly those afterwards. I'll update the CLAUDE.md line about the `:Test` label to describe this instead. Tests assert that their own items are present, never exact counts, because seed data lives in the same database.
- **Port.** On macOS, AirPlay uses port 5000, so the run command becomes `flask --app app run --debug --port 5001`. I'll update CLAUDE.md and the README.
